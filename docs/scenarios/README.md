# 画布模拟工作场景

这是一套给**人**在 DSH 工作区里实际开聊天、跑完再拖进画布的工作包，不是画布 JSON 快照。

## 目录

- `<workspace>\canvas-scenario\S1\inputs\`：需求文件
- `<workspace>\canvas-scenario\S2\inputs\`：事故日志
- `<workspace>\canvas-scenario\S3\inputs\`：草案与测试计划
- 聊天 prompt 和画布任务：本目录下的 `work-packages/`

## 三个场景

| 场景 | 两个真实聊天 | 输入文件 | 画布任务 |
| --- | --- | --- | --- |
| S1 缓存决策 | 旧方案 24h / 复审 2h | cache-requirements.md | 列冲突、对照 ≤10 分钟、给推荐但不拍板 |
| S2 502 复盘 | 初步排查 / 证书链定位 | incident-2026-10-19.log | 时间线、根因/证据、未知影响、行动项 |
| S3 V2 评审 | 范围讨论 / 草案评审 | design-draft-v2.md、test-plan-v2.md | 阻塞项、最小修改、测试缺口 |

## 跑法

1. 每个场景开两个新会话，分别粘贴 `work-packages/Sx/01...` 和 `02...` 的内容并发送；
2. 等两个会话都完成；
3. 打开画布，把这两个会话从素材库拖入；
4. 把对应 `inputs/` 文件拖入；
5. 新建/选中「新对话」节点，粘贴 `03-canvas-task.md` 到提示词或任务指令；
6. 连线，确认「N 个来源已连接」，先预览，再创建并预填。

## 结果怎么对比

- 打分用 `RUBRIC.md`（12 项，每项 0–2，总分 24）；
- 最低要求看 `EXPECTED.md` 的必错项：冲突、事实边界、缺失信息任一项 0 分，直接标记“不可用于决策”；
- 编译侧（字符/token/预览耗时）和模型侧（分数）分开记录；
- 同一场景、同一模式、同一模型下比较，才有意义；
- 本轮作为 V1 基线，改摘要策略后用同一批场景重跑。

## 为什么这样设计

- 两个聊天故意分开，模拟“不同时间点、不同立场”的真实历史；
- 每个场景都埋了冲突或缺口，避免只测“能不能跑通”；
- 文件是真实可读的 markdown/log，不是假字符串；
- 任务 prompt 明确要求来源编号、并列冲突、未知不编造，方便判分。
