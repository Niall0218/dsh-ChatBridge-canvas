## 四、这次暴露的真问题

### 1. 回答普遍超长，“一页”指令无效

S1 要求“一页”，实际约 4,000 字符；S3 约 7,000 字符；S2 甚至调工具写了 220 行文件。  
不是模型不听话，而是画布给的任务指令只有一句“输出一页”，没有硬性字数和结构上限。下一版应在编译器里追加“篇幅预算”，例如“正文 ≤1200 字，表格不计；超出请只保留结论”。

### 2. S2 暴露了“转述 vs 原始日志”的冲突，但工具调用让成本翻倍

S2 新对话发现“3% 在原始日志里不存在”“edge-1 14:04 有 8%”，这是画布把两个会话的转述和日志原文并列后的真实价值。  
但它选择调用文件工具读日志、并写了一份 postmortem 到工作区，导致 133K tok。原因是文件是“路径引用”而不是内联。  
改进：文件节点默认内联（小文件），或在预览里明确“该文件未内联，将触发工具读取”。

### 3. 拖线到空白处会自动新建 chat，容易越拖越多

自动化里因为落点偏了，连续生成了 5 个 chat 节点，连线分散，预览显示 1 个来源。  
真实用户也可能遇到：拖线没对准目标就多一个空 chat。  
改进：拖线到空白处时先弹确认/提示，或只在距已有 chat 超过一定距离时才新建；同时在拖线时高亮可接收节点。

### 4. 检查器打开时画布过窄，拖线落点容易被遮挡

S1 第一次预览 0 来源就是这个原因。1600 宽下打开检查器后画布只剩 216px。  
改进：拖线时临时隐藏检查器，或把检查器改为覆盖层而不是挤压画布。

### 5. 信息密度仍受“摘要=最近 10 条”限制

三份回答质量高，但摘要里仍混有过程流水；S1 的第一段甚至还是“首条用户消息 + 请给出 1/2/3”。  
改进方向仍是规则版摘要：优先结论句、保留每轮用户追问、保留数字与否定判断。

## 五、下一版优先级建议

1. **任务模板加篇幅预算**（最低成本，直接改善 3 项扣分）。
2. **小文件默认内联，或预览里标注“将触发工具读取”**（S2 成本翻倍的主因）。
3. **拖线交互修复**：落点提示、节点高亮、避免空白处误建 chat。
4. **检查器不挤压画布**（悬浮/抽屉）。
5. **摘要规则改版**：结论句优先 + 保留用户追问 + 数字/否定词保留。
