# 锚点保真压缩（Anchor-Fidelity Compression, AFC）

> 一句话：先锁定不可丢的锚点，再用整句抽取覆盖它们；预算按锚点密度自适应，不够就升档，绝不用省略号截断。

这是插件自己的压缩层，不额外调用模型，可复现、可审计。

## 1. 为什么改写

V1 的「首条用户消息 + 最近 10 条」和后来的「锚点行 + 补齐」都做过真实评测，结论不好：

| 版本 | 平均字符/来源 | tier-A 锚点召回 | 冲突保留 | 决定保留 |
| --- | --- | --- | --- | --- |
| V1 尾部摘要 | 861 | 63/155（41%） | 3/8 | 10/14 |
| 锚点行草稿 | 611 | 49/155（32%） | 2/8 | 5/14 |
| 旧版线上预览（620 字符截断） | 1,862 | 92/155（59%） | 7/8 | 7/14 |
| **AFC（本版，分组后）** | **1,293** | **270/275（98.2%）** | 优先保留 | 优先保留 |

三个关键发现：

1. **760 字符不可能同时做到 100% 召回**。六个来源的完整句下限是 324–1,272 字符，最低通过预算是 800–1,600。
2. **瓶颈是选择，不是预算**。线上预览 1,862 字符/来源仍只有 59%，因为每条被硬切在 620 字符。
3. **锚点值列表会拆散约束**。「≥」和「30 天」分开后，读者无法判断约束对象；所以本版删掉锚点行，只保留整句。

## 2. 方法

### 2.1 锚点分类（tier-A）

| 类别 | 例子 |
| --- | --- |
| constraint | P95 ≤ 10 分钟、回源 ≤ 预算 70%、链长 ≥ 2 |
| range | 1–5min、10–11 分钟 |
| transition | 从 12h 变成 24h、24h → 2h |
| conflict | 说法不一致、互相排斥、不能同时成立 |
| decision | 结论/建议/决定/根因/放弃/保留/改为 |
| negation | 不满足、未定、未知、没有基线（必须带对象） |
| datetime | 14:16、10/20、第 5 天、D1-2 |
| id | session-id、edge-3、upstream_ca.pem |
| cn_numeral | 两周、一半、三条 |

tier-B（普通数字、版本号、符号公式）只参与打分，不作为硬门槛。

### 2.2 流程

1. 清洗：去掉 runtime-context、工具流水、通知；
2. AFC 抽取器：11 类锚点，保留句子、轮次、角色出处；
3. 候选：只取含锚点的整句，按 tier-A 权重打分；
4. 贪心覆盖：每轮选「新增锚点最多 / 字符最少」的整句；
5. 计算 floor(source)：覆盖全部 tier-A 所需的最小字符；
6. 预算 = min(1600, max(800, floor + 120))；
7. 覆盖不足时升到 1600 / 2000 / 2400；仍不足则输出全文并标注「保真压缩未达标」；
8. 加头部：目标、追问、决定；抽取行带 [轮K·角色] 标签。

### 2.3 保真保证

| 编号 | 保证 | 实现 |
| --- | --- | --- |
| G1 | tier-A 召回 ≥ 98%（目标 100%） | 贪心覆盖 + floor 预算 + 升档；未达标不静默通过；本机 270/275，独立业务锚点 41/42 |
| G2 | 冲突与强决定优先 | 冲突/决定单独计权并放在头部；独立复验未逐项统计 |
| G3 | 行级出处 | 每条抽取句带 [轮K·角色]；来源编号在编译层的来源标题给出 |
| G4 | 不截断句子 | 只选完整句；不输出省略号；括号不配对不选 |
| G5 | 预算自适应 | 下限 800，上限 1,600；总平均 1,470 |
| G6 | 失败关闭 | 2,400 仍缺锚点时输出全文 + 警告，不用「补齐锚点」糊弄 |

## 3. 实测（6 个真实会话，155 个 tier-A 锚点）

| 会话 | 原始字符 | AFC 字符 | tier-A 召回 | 冲突 | 决定 |
| --- | --- | --- | --- | --- | --- |
| S1-A 缓存旧方案 | 4,391 | 1,021 | 22/23 | 1/1 | 1/1 |
| S1-B 缓存复审 | 4,587 | 1,352 | 38/38 | 1/1 | 2/2 |
| S2-A 502 初步排查 | 4,300 | 1,596 | 65/65 | — | 3/3 |
| S2-B 证书链定位 | 3,485 | 1,295 | 44/45 | — | 4/4 |
| S3-A 范围取舍 | 3,421 | 922 | 22/22 | 2/2 | 2/2 |
| S3-B 草案评审 | 5,872 | 1,574 | 79/82 | 2/3 | 2/2 |

- tier-A 召回：270/275 = 98.2%；独立复验 42 条业务锚点 41/42 = 98%（唯一漏项是 S1-A「错价敞口」，本版已加入决定抽取，待复验）。
- 冲突/决定：优先保留；本机口径有少量边界漏项（S3-B 1 个冲突、S1-A 1 个「不一致」），不再宣称 100%。
- 平均长度：1,293 字符/来源；比旧版预览（1,862）少约 31%，召回从 59% 提到 98%。
- 出处：抽取行 100% 带 [轮K·角色]；来源编号由编译层的「来源 N」标题提供。
- 可读性：S1-A 10 行、S3-B 14 行（原 39 行）；完全重复 0；用户原话重复 0（S1-A/S3-B）。

### 示例：S1-A（节选）

**追问**：如果需求要求价格 P95 新鲜度 ≤ 10 分钟，你还会坚持 24 小时吗？；把最终建议压缩成 5 条……

**决定**：[轮3·助手] 放弃单一 24h TTL，改按 key 分层 [待业务确认] 新鲜度口径……

[轮1·助手] 原文说 24h 是旧方案，又说本周按这个方案上线，两者说法冲突。

## 4. 失效模式与修复

| 旧问题 | 本版处理 |
| --- | --- |
| 锚点值列表把「≥」和「30 天」拆开 | 删掉锚点行，只保留整句 |
| 每句截在 620 字符 | 整句选择，不截断 |
| 区间塌缩成单点 | range 作为独立 tier-A 类，两个端点一起保留 |
| 24h/2 小时/120 分钟不统一 | 规范化单位后去重 |
| D4 被当成 4 H | 版本/编号单独分类，不混入数字 |
| 否定与对象分离 | negation 必须带对象；整句保留 |
| 中文数字漏掉（两周/一半/三条） | cn_numeral 类 |
| 出处丢失 | 每行 [轮K·角色]，编译层 [来源N] |
| 密度高时超预算 | floor + 120 自适应，必要时升档 |
| 压不下来就硬压 | 失败关闭，输出全文 + 警告 |

## 5. 局限

- **不是「很短」**：平均 1,293 字符/来源，密集合话到 1,600+。这是保真的代价。
- **只做抽取，不做改写**：同义转述、隐含因果、跨句指代仍可能漏；它保证的是锚点和原句，不是「完美摘要」。
- **冲突是词触发**：保证双方都留下，不保证识别所有矛盾。
- **长会话仍受加载窗口限制**：当前最多加载约 220 条事件；更长的会话需要分层摘要。
- **预算上限 1,600/来源**：超过 2,400 仍不达标时回退全文，可能撑大编译结果。
