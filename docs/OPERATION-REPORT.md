# DSH Context Canvas V1 操作测试报告

版本：V1 实例测试套件  
日期：2026-10-20  
测试目标：验证画布从“选择来源”到“预览上下文”再到“创建并预填”的完整闭环，并找出第一版在来源管理、冲突处理、长文本、导入容错和持久化方面的不足。

## 二、测试 1：正常多来源编排

### 目的

验证多个历史对话、文件和任务要求能否按照连线顺序合并成一份可审阅上下文。

### 操作步骤

1. 打开侧边栏「画布」。
2. 点击右上角「更多」。
3. 选择「导入画布 JSON」。
4. 导入：

   ```text
   <workspace>\dsh-context-canvas\docs\examples\01-product-review.json
   ```

5. 等待画布出现 5 个节点和 4 条连线。
6. 选中右侧的「新对话·产品评审」节点。
7. 在检查器中选择一个目标工作区。
8. 点击「预览上下文」。
9. 观察预览中的统计、来源编号和正文顺序。
10. 在来源列表中禁用「技术方案评估」对应的连线。
11. 再次点击「预览上下文」。
12. 重新启用该连线，并把「任务要求」移动到第一位，再次预览。
13. 在预览文本中修改一句任务要求。
14. 点击「创建并预填」。
15. 进入新会话输入框，检查上下文是否已经填入。

### 预期结果

- 画布显示 5 个节点、4 条连线。
- 预览统计显示：2 个历史对话、1 个文件、1 条任务要求。
- 来源顺序为：

  ```text
  产品需求讨论
  技术方案评估
  context-spec.md
  任务要求
  ```

- 文件内容位于 `text` 代码块中。
- 禁用来源后，该来源从上下文正文消失，禁用数量增加。
- 调整连线顺序后，来源编号和正文顺序同步变化。
- 修改预览文本后，创建的新会话输入框使用修改后的文本。
- 创建后返回画布时，目标节点显示已创建状态。

### 重点观察

- 来源编号是否稳定且唯一。
- 禁用来源是否真的不进入正文。
- 预览编辑内容是否被创建流程覆盖。
- 创建后节点状态和结果会话 ID 是否保存。

## 三、测试 2：冲突资料审阅

### 目的

验证画布遇到相互矛盾的历史资料时，是否保留双方内容并提示新对话处理，而不是静默选择一方。

### 操作步骤

1. 清空画布。
2. 导入：

   ```text
   <workspace>\dsh-context-canvas\docs\examples\02-conflict-review.json
   ```

3. 选中「新对话·冲突审阅」节点。
4. 选择目标工作区。
5. 点击「预览上下文」。
6. 确认预览中同时出现：

   ```text
   24 小时缓存方案
   2 小时缓存方案
   ```

7. 禁用「最新方案决定」连线。
8. 再次预览，确认 2 小时方案消失。
9. 重新启用该连线，并将其移动到第一位。
10. 再次预览，检查来源编号是否随顺序改变。

### 预期结果

- 两个冲突主张都被保留。
- 上下文底部出现“冲突时并列列出，不要静默选择”的工作约定。
- 禁用来源后，正文中不再出现该来源。
- 画布不会自动判断 24 小时或 2 小时哪个正确。

### 重点观察

- 是否有来源被错误覆盖。
- 来源顺序变化后，编号是否错乱。
- 新对话是否能看到足够的时间和来源信息来判断冲突。
- UI 是否明确告诉用户当前版本没有自动冲突检测。

## 四、测试 3：长文本与路径引用

### 目的

验证文件路径引用、文件内联、读取和超长内容截断行为。

### 操作步骤

1. 清空画布。
2. 导入：

   ```text
   <workspace>\dsh-context-canvas\docs\examples\03-long-and-reference.json
   ```

3. 选中「新对话·长上下文」节点。
4. 选择目标工作区。
5. 点击「预览上下文」。
6. 检查两个文件节点：

   ```text
   context-spec.md（路径引用）
   context-spec.md（超长内联）
   ```

7. 确认路径引用节点只显示路径和按需读取提示。
8. 确认超长内联节点显示 `text` 代码块。
9. 记录预览中的字符数和 token 估算。
10. 将路径引用节点改为“内联文本”。
11. 点击文件节点的「读取」。
12. 再次预览，比较读取前后的上下文变化。
13. 尝试把超长内联内容复制出来，检查代码围栏是否完整。

### 预期结果

- 路径引用不会把文件正文直接塞进上下文。
- 内联文件会出现在 `text` 代码块中。
- 超长文本会在文件内联上限附近截断。
- 预览统计能够反映长文本带来的字符数和 token 数增长。
- token 数明确只是估算值。

### 重点观察

- 截断是否破坏 Markdown 或代码围栏。
- 文件读取失败时是否有明确错误提示。
- 文件路径是否完整显示。
- 路径引用和内联模式是否容易区分。
- 长文本是否导致预览卡死、布局溢出或按钮失效。

## 五、测试 4：导入清洗和异常数据

### 目的

验证导入非法或不完整 JSON 时，画布是否能稳定加载，并清理无效节点和连线。

### 操作步骤

1. 清空画布。
2. 导入：

   ```text
   docs/examples/04-import-sanitize.json
   ```

3. 观察画布加载是否报错。
4. 记录最终显示的节点数量和连线数量。
5. 选中「脏数据测试目标」节点。
6. 点击「预览上下文」。
7. 观察禁用来源、重复连线和空提示词是否影响预览。
8. 刷新页面。
9. 检查画布布局和缩放是否仍然可用。

### 预期结果

- 页面不崩溃，画布可以正常显示。
- 重复节点只保留第一份。
- 未知节点类型被归一化，不导致导入失败。
- 重复连线只保留一条。
- 缺失端点的连线被丢弃。
- 自连线被丢弃。
- 非法 viewport 坐标回退，缩放被限制在允许范围内。
- 空提示词不会生成有效任务要求。
- 刷新后画布仍可操作。

### 重点观察

- 导入后是否给出清洗提示。
- 用户能否知道哪些节点和连线被丢弃。
- 非法数据是否造成节点重叠或缩放异常。
- 预览统计是否把禁用来源错误计算为有效来源。

## 六、持久化回归

在完成任意一轮测试后执行：

1. 拖动两个节点到新位置。
2. 修改画布名称。
3. 切换一次缩放比例。
4. 刷新 DSH 页面。
5. 返回「画布」。
6. 检查节点位置、名称、连线、来源开关和缩放是否恢复。
7. 点击「更多 → 导出画布 JSON」。
8. 用文本编辑器打开导出的 JSON，检查节点和连线是否完整。

预期结果：刷新不会丢失画布结构，导出的 JSON 可以重新导入。

## 七、已知限制，测试时不要误判为新问题

以下现象属于 V1 已知边界，仍然可以记录体验问题，但不要当作“新增功能回归”：

- 示例中的会话 ID 是合成值；点击“刷新摘要”可能提示找不到会话。
- “创建并发送”需要当前 profile 配置可用模型。
- V1 不会自动裁决冲突来源。
- 超长文件可能被截断，文件读取目前使用 DSH 预览接口。
- 没有文件哈希和版本快照。
- 没有多画布、协作和结构化记忆库。
