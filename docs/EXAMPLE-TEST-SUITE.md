# DSH Context Canvas V1 实例测试套件

这套实例用于验证第一版画布的“选择来源 → 编排 → 预览 → 创建”能力。实例使用的是合成的对话摘要和本地文件，不会修改历史对话；导入后建议先只点“预览上下文”，确认结果后再决定是否创建新对话。

## 文件清单

| 文件 | 用途 | 主要覆盖 |
| --- | --- | --- |
| `01-product-review.json` | 正常产品评审编排 | 2 个对话 + 1 个内联文件 + 1 个任务要求、来源顺序、预览统计 |
| `02-conflict-review.json` | 冲突资料审阅 | 两个相互矛盾的决定、并列呈现、禁用来源 |
| `03-long-and-reference.json` | 长文本与文件引用 | 路径引用、约 18k 字符内联文本、截断与 token 估算 |
| `04-import-sanitize.json` | 导入边界 | 重复节点、重复连线、未知节点类型、缺失端点、自连线、非法 viewport |
| `context-spec.md` | 可读取的合成文件 | 文件节点“读取”和“内联”模式 |

## 如何运行

1. 打开 DSH 的「画布」。
2. 选择「更多 → 导入画布 JSON」，导入一个实例文件。
3. 选中右侧「新对话」节点，在检查器中选择目标工作区。
4. 先点击「预览上下文」，记录来源数量、字符数、token 估算和警告。
5. 在来源列表中切换启用/禁用或调整顺序，再次预览，观察正文是否变化。
6. 第一轮测试只使用「创建并预填」；创建后在输入框检查上下文，不要直接发送。
7. 测试结束后可用「更多 → 清空画布」清理。实例文件本身不会被改写。

> 示例里的 `sessionId` 是故意使用的合成值。因为对话节点已经带有缓存摘要，预览可以验证编译器；如果点击刷新摘要，会得到“找不到会话”一类警告，这是测试“来源失效”边界的预期结果。

## 实例 01：产品评审主流程

**操作**：导入 `01-product-review.json`，预览 `新对话·产品评审`。

**应看到**：

- 4 个启用来源，统计为 2 个历史对话、1 个文件、1 条任务要求。
- 正文顺序为：产品需求讨论 → 技术方案评估 → `context-spec.md` 内联文本 → 任务要求。
- 文件正文位于 `text` 代码围栏中，末尾有“工作约定”。
- 预览可编辑；编辑后创建会把编辑后的文本写入新会话输入框。

**进一步操作**：禁用“技术方案评估”边，再次预览。统计中的 `disabled` 应增加，正文中该来源应消失，其他来源顺序不变。

**验证能力**：多源合并、顺序稳定、文件内联、任务指令优先、可审阅后创建。

## 实例 02：冲突资料

**操作**：导入 `02-conflict-review.json`，预览 `新对话·冲突审阅`。

**应看到**：

- 两个对话分别主张缓存有效期为 24 小时和 2 小时。
- 画布不会自动判定哪个正确；底部工作约定会要求新对话并列列出冲突。
- 任务要求要求输出来源、主张、时间和待确认决定。

**进一步操作**：把 `edge-b` 禁用，再次预览，确认 2 小时主张消失；重新启用并把它移到第一位，确认来源编号和正文顺序随 `order` 改变。

**验证能力**：冲突资料保留、来源开关、来源重排。

**暴露的不足**：V1 没有自动冲突检测、时间线判断或“最新决定优先”规则。它只能把冲突交给新对话处理。

## 实例 03：长文本与引用

**操作**：导入 `03-long-and-reference.json`，预览 `新对话·长上下文`。

**应看到**：

- `context-spec.md（路径引用）` 只出现路径和按需读取提示，不包含正文。
- `context-spec.md（超长内联）` 出现 `text` 代码块；内容会按文件内联上限截断。
- 预览统计的字符数和 token 数明显高于实例 01，但 token 只是估算值。

**进一步操作**：将第一个文件改为“内联文本”，点“读取”，再预览；比较“读取后内联”和“路径引用”的正文差异。

**验证能力**：文件两种使用模式、超长文本截断、预览统计。

**暴露的不足**：V1 没有文件哈希和版本快照；文件被修改或删除时，只能在读取阶段报错。超长文件没有分页或摘要，内联上限前的内容可能被截断。

## 实例 04：导入清洗边界

**操作**：导入 `04-import-sanitize.json`，观察画布节点和连线数量，再预览 `脏数据测试目标`。

**预期归一化结果**：

- 相同 `id` 的第二个节点被丢弃。
- 未知类型 `alien` 被归一化成对话节点；它的连线是禁用状态，因此不会进入正文。
- 相同起点和终点的第二条连线被丢弃。
- 缺失端点的连线和自连线被丢弃。
- `viewport.scale` 被限制在允许范围内，非法坐标回退为默认值。
- 空提示词节点可以保留在画布上，但编译时不会生成有效任务要求。

**验证能力**：JSON 导入容错、重复清理、无效连线清理、缩放归一化。

**暴露的不足**：导入清洗不会把修正后的 JSON 回写到原文件，也没有逐项告诉用户哪些字段被修正；复杂脏数据只能通过画布结果间接判断。

## 能力结论

当前 V1 适合做“人工选择来源、人工检查上下文、再开始一次新工作”的编排器。它已经能把多个来源稳定地编译成可读文本，并保留来源编号、路径和工作约定。

它还不适合承担自动知识库、自动冲突裁决、文件版本管理或长文档压缩。下一轮最有价值的增强顺序是：来源失效/更新时间提示 → 文件版本和哈希 → 冲突候选并列审阅 → 大文件分页或摘要 → 多画布与模板。
